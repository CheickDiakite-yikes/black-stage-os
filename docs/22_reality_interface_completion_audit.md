# 22 Reality Interface Completion Audit

Date: 2026-05-10
Status: Not complete

## Objective Restated As Deliverables

Blackstage is complete only when the repo can demonstrate a working reality interface that:

1. Begins as a calm black living render field.
2. Accepts natural voice, text, and multimodal precision input.
3. Turns intent into a persistent intent thread.
4. Dynamically forms documents, models, maps, browsers, timelines, simulations, memories, approvals, agent activity, and final artifacts.
5. Shows visible, auditable, interruptible, non-noisy agent labor.
6. Gates high-impact actions behind explicit human approval.
7. Lets the user manipulate outputs through speech, text, gesture, and correction.
8. Ends in usable artifacts the user can edit, approve, export, or act on.
9. Preserves the calm, cinematic, non-chatbot, non-dashboard Black Stage feeling.
10. Has instrumentation and build evidence from day one.
11. Provides a path from simulation into a real background agentic harness.

## Gaps That Block Goal Completion

The goal is not complete yet. The largest remaining gaps are:

1. Live Realtime voice is not connected by default. The contract, trusted-server request envelope, route handler, local broker server mount, server-side OpenAI exchange adapter, browser-safe readiness/proof clients, disabled browser SDP exchange adapter, explicit Stage Web SDP bridge, visible Stage Web live arming approval, broker readiness approval-state reporting, local live-exchange approval header, redacted live-smoke preflight, skip-gated live smoke command, optional `.blackstage/` redacted proof writer, read-only broker proof index, Stage Web proof-count status, Realtime server-event parser, and Stage event mapper exist, and local browser-native assistant speech works, but no armed local OpenAI Realtime smoke or microphone stream has been run yet.
2. Live agentic work is not connected by default. Codex, Codex App Server handoffs, Agents SDK, and Symphony-inspired orchestration are now represented by root `WORKFLOW.md`, typed local contracts, fixtures, a localhost runner service, a disabled Codex subprocess boundary, local approval-token arming, bounded workspace preparation, local run proof packets, read-only proof summaries, and Stage Web read-only proof counts, not default live workers.
3. Browser, map, model, document, memory, and simulation objects are still simulated or local-only. Browser, map, model, document, and simulation objects can now be retargeted, updated, annotated, or locally run by command, but they do not browse, write files, call map/model/simulation services, or control live external tools yet.
4. Artifact action is still local-only. The user can edit, approve, export, and prepare an approval-gated harness action packet, but cannot safely execute a real external workflow yet.
5. Multimodal context is still shallow. Text attachments become local excerpts, image attachments show session-only local previews, and CSV/JSON attachments now show local structure summaries, but model-backed image understanding and deeper context parsing are not implemented.
6. Speech correction is bounded. Typed and spoken deterministic object commands, object rename, and artifact revision work, but richer natural-language edits across arbitrary objects are not implemented.
7. Memory is local-only. It now has approval-gated write/delete semantics, redacted inspection, deterministic local recall ranking, cross-thread review UI, and typed background-agent memory policy enforcement in dry-run plans, but no live provider-backed memory enforcement has run yet.
8. The current visual proof is a browser prototype, not yet a full "computer disappears" environment.

## Next Highest-Leverage Slice

Promote the explicit Stage Web Realtime bridge into a real local live-session smoke while keeping simulation as the default:

- Keep the browser client on SDP-only Realtime exchange, with no standard API key or safety identifier exposed.
- Run `pnpm smoke:realtime` with a local API key, safety identifier, and approval phrase, without committing secrets or raw SDP.
- Add microphone/audio-track handling only after the no-audio SDP bridge remains stable and auditable.
- Preserve the Codex/Symphony/Agents SDK harness as background labor behind Blackstage-owned approvals.
- Keep Realtime text/audio/tool events mapped into the existing Stage event log.

This moves the prototype toward real directed intelligence without putting long-lived API keys in the browser or letting external tools bypass the stage.
