# 14 Research Protocol

## Research mission

Blackstage is both a product and a research program.

We are studying two things:

1. The future of human-computer interaction through voice-native agentic render interfaces.
2. The process of building complex AI products with AI coding agents.

## Research tracks

### Track A: Product/HCI research

Core question:

> Does a living render field organized around intent improve user understanding, trust, and task execution compared with traditional chat or app-based interfaces?

Subquestions:

- Do users understand intent threads?
- Does visible agent labor increase trust?
- Do approval rituals reduce fear without causing friction?
- What types of tasks benefit most from a render field?
- When is voice better than text?
- When does the user need direct manipulation?
- What makes the interface feel magical vs confusing?
- Does the black stage create calm or intimidation?

### Track B: AI-assisted product building research

Core question:

> How can a small founding team use AI coding agents to build a novel, complex product faster while preserving taste, architecture, and research rigor?

Subquestions:

- What docs improve Codex output most?
- Which tasks should be assigned to Codex vs handled by humans?
- How often does Codex drift from product taste?
- How do subagents affect review quality?
- What prompt patterns produce better implementation?
- What failure modes repeat?
- How does AGENTS.md evolve over time?
- Can we quantify development acceleration?
- Can we publish a reproducible AI-building methodology?

## Study design

### Internal build study

Every meaningful Codex task becomes a data point.

Capture:

- Task description.
- Prompt.
- Docs referenced.
- Time or iteration count.
- First-pass success/failure.
- Human interventions.
- Verification results.
- Product impact.
- Research insight.

### Product demo study

For each demo/user session:

Capture:

- User profile.
- Task scenario.
- First reaction.
- Confusion points.
- Trust moments.
- Delight moments.
- Direct quotes.
- Completion outcome.
- "I saw the future" score.
- Suggestions.

### Comparative study

Compare Blackstage-style render interface against chat-only flow.

Example task:

> "Help me plan a seed raise and produce the next five investor actions."

Conditions:

- Chat-only assistant.
- Blackstage render field.

Measure:

- Time to understand plan.
- User trust.
- Perceived control.
- Artifact usefulness.
- Cognitive load.
- Preference.

## Key metrics

### Product metrics

- Time to first meaningful render.
- Time to artifact.
- Number of user interventions.
- Approval clarity score.
- Agent trust score.
- User perceived control score.
- Wow score.
- Task completion score.
- Artifact usefulness score.

### AI-building metrics

- Codex first-pass task success rate.
- Number of correction turns.
- Verification pass rate.
- Docs referenced per task.
- Prompt length vs quality.
- Repeated failure rate.
- Human rework time.
- PR review severity count.
- Research log completion rate.

## Research ethics

- Do not mislead users about simulated vs real agent actions.
- Do not record private content without consent.
- Do not store sensitive data in research logs.
- Label internal findings vs user-study findings.
- Be honest about limitations.
- Publish failures and constraints, not only successes.

## Data capture template

Use `templates/research_session_log.md`.

## Publication-worthy findings

Potential findings include:

- A taxonomy of intent-thread interfaces.
- Design principles for visible agent labor.
- Human approval rituals for agentic systems.
- Metrics for agentic UI trust.
- A methodology for AI-assisted product development.
- Failure modes of coding agents in novel product builds.
- How living render fields change user cognition.

## Research cadence

### Daily

- Log build tasks and product insights.

### Weekly

- Summarize Codex performance.
- Update docs and AGENTS.md.
- Identify repeated failure modes.
- Choose one research question to focus on.

### Monthly

- Produce a research memo.
- Publish selected non-sensitive findings.
- Update roadmap based on evidence.
